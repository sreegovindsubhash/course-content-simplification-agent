## Top-Level Overview

Build a beginner-friendly web application that accepts academic text, lets the student choose a learner level (Beginner / Intermediate / Advanced), and returns a simplified explanation generated by **IBM Granite** via **IBM watsonx.ai**.

The application has two parts:

- **Frontend** — a single HTML page styled with plain CSS, served by Flask itself (no separate JS framework).
- **Backend** — a small Python Flask server that receives the form submission, calls the watsonx.ai REST API using the `ibm-watsonx-ai` SDK, and returns the result.

There is no database, no user accounts, and no external infrastructure beyond IBM Cloud Lite.

---

## Architecture Diagram (Text)

```
Browser (HTML form)
      |
      | HTTP POST /simplify
      v
Flask app (app.py)
      |
      | ibm-watsonx-ai SDK call
      v
IBM watsonx.ai  -->  IBM Granite model
      |
      | Simplified text response
      v
Flask renders result back to the same HTML page
```

2. Scroll to **Services and integrations** → click **Associate service**.
3. If you do not yet have a Watson Machine Learning (WML) instance, click **New service** → search for **Watson Machine Learning** → choose the **Lite** plan → create it.
4. Select your WML instance and click **Associate**. The project now has AI model access.

**C. Get your Project ID**
1. Stay on the project **Manage** tab.
2. Under **General**, find the **Project ID** field (a long string of letters and numbers like `abc123de-...`).

**D. Create an IBM Cloud API key**
1. Go to [https://cloud.ibm.com/iam/apikeys](https://cloud.ibm.com/iam/apikeys).
2. Click **Create an IBM Cloud API key**.
3. Give it a name (e.g. `course-simplifier-key`) and click **Create**.

5. This is your `WATSONX_API_KEY`.

### Sub-Task 3 — Backend Flask Application

**Status:** `[x] done`

**Intent:**
Write `app.py` — the entire backend. It loads credentials, serves the HTML page, receives the form POST, constructs a prompt appropriate for the chosen learner level, calls IBM Granite via watsonx.ai, parses the response, and renders the result back into the template.

**Expected Outcomes:**
- Running `python app.py` starts a local server on `http://127.0.0.1:5000`.
- The `/` route renders `index.html` (GET).
- The `/simplify` route (POST) reads `content` and `level` from the form, calls watsonx.ai, and re-renders `index.html` with the response.
- If credentials are missing or the API call fails, the page shows a human-readable error message instead of crashing.
- The model used is `ibm/granite-4-h-small` — confirmed in Sub-Task 0 against the active watsonx.ai Runtime in us-south (Dallas).
- The code is under ~100 lines and has inline comments explaining each section.

**Todo List:**
1. Import `flask`, `os`, `dotenv`, and `ibm_watsonx_ai` at the top of `app.py`.
2. Call `load_dotenv()` to load `.env` before reading environment variables.
3. Initialise the watsonx.ai `ModelInference` client using `WATSONX_API_KEY`, `WATSONX_PROJECT_ID`, and `WATSONX_URL`.
4. Define the `/` GET route that returns `render_template('index.html')`.
5. Define the `/simplify` POST route:
   a. Read `content` and `level` from `request.form`.
   b. Build a prompt string that instructs Granite to simplify for the chosen level (see Prompt Design note below).
   c. Call `model.generate_text(prompt)` (or equivalent SDK method).
   d. Parse the returned text — attempt to split out Key Concepts, Key Points, and Summary if the model returns them in a structured format.
   e. Call `render_template('index.html', result=..., concepts=..., key_points=..., summary=..., original_content=..., selected_level=...)`.
6. Wrap the API call in a try/except and pass `error=str(e)` to the template on failure.
7. Add `if __name__ == '__main__': app.run(debug=True)` at the bottom.

**Prompt Design:**
The prompt sent to Granite should follow this structure (adapt wording per level):

```
You are an educational assistant. Simplify the following course content for a {level} learner.

Provide your response in this exact format:
SIMPLIFIED EXPLANATION:
<your simplified explanation here>

KEY CONCEPTS:
<bullet list of key concepts>

KEY POINTS:
<bullet list of key points to remember>

SUMMARY:
<one or two sentence summary>

Course content to simplify:
{content}
```

This structured prompt makes parsing reliable without needing JSON.

**Relevant Context:**
- `ibm-watsonx-ai` SDK class: `ModelInference` from `ibm_watsonx_ai.foundation_models`.
- Authentication: `Credentials(url=WATSONX_URL, api_key=WATSONX_API_KEY)`.
- Model parameters to pass: `max_new_tokens` (e.g. 800), `temperature` (e.g. 0.3 for factual output).
- The model ID to use in `app.py` is `ibm/granite-4-h-small`. Read it from the `WATSONX_MODEL_ID` environment variable (set in `.env`) rather than hardcoding the string, so it can be changed without editing Python code.

## Potential Risks and Beginner Mitigations

| Risk | Mitigation |
|---|---|
| IBM Granite model ID is unknown before setup | Sub-Task 0 step F resolves this — check Prompt Lab in your watsonx.ai project and record the exact model ID before writing any backend code |
| watsonx.ai SDK version mismatch | Pin the SDK version in `requirements.txt` after confirming it works |
| API key accidentally committed to Git | `.gitignore` excludes `.env`; double-check with `git status` before every commit |
| Prompt returns unstructured text (no section headers) | Parse defensively — if headers are missing, show the full raw response as the simplified explanation |
| IBM Cloud Lite rate limits | Lite tier has token/minute limits; avoid rapid repeated submissions during the demo |
| Flask debug mode in production | `debug=True` is fine for local demo; add a note in README that it must be `False` for any public deployment |
| Windows path issues with venv activation | Use `.venv\Scripts\activate` on Windows (not `source .venv/bin/activate`) |
